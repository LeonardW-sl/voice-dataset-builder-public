# voice-dataset-builder-public

目标：从混有主播、背景音乐和游戏音效的直播录音中，整理出“只有目标主播说话、内容完整、文字对应”的训练素材。本仓库做数据处理，不做语音合成模型训练。

## 最新方法与当前状态（私有批次；公开代码为较早快照）

> 本节说明**当前私有工作流**。下文的状态、用户反馈、问题表与脚本说明对应**较早的公开快照**，不得把两者混为一谈。

当前批次的实际流程（在私有环境执行，不在本仓库内）：

```text
以 30 秒窗口 / 15 秒步长截取分析窗口，保存 Qwen3-ASR-1.7B + Qwen3-ForcedAligner-0.6B 的原始结果
  → 只从这些缓存结果组装，不重新推理
  → 回到原 MP3，加回窗口偏移裁出句级音频
  → 生成离线 review 页，由人逐句评价
  → 汇总人工评价统计
```

- **模型与批次**：当前用 Qwen3-ASR-1.7B 转写、Qwen3-ForcedAligner-0.6B 做逐字对齐。旧 FireRedAed / Whisper 路线属于更早批次，**不是当前批次**；下方脚本说明里的同名工具只描述旧快照。
- **公开代码边界**：本仓库是较早快照，`scripts/` 中**没有** `05_asr_qwen` 与 `sentence_ops`；不要把这些公开文件描述为已实现本节的最新功能，也不要据此推断私有批次的产物可由公开代码复现。
- **固定窗口的局限**：当前是固定 30 秒窗口 / 15 秒步长，**没有运行 VAD、说话人核验或去音乐**；不能声称已做说话检测、目标主播过滤或音乐分离。
- **三层音频要分清**：**原音完整文件**是唯一来源；**截取分析窗口**只是带起点偏移的只读分析区间，用来跑识别与对齐；**句级音频与上下文**是回原 MP3 按窗口偏移裁出的短句及其前后参照。窗口边界不等于句子边界，回听上下文也不等于精确配对。
- **为何保留上下文**：结果出现冲突、位置异常、落在窗口边缘或与相邻句重叠时，会保留上下文供人工判断；**人工接受只表示当时可用，不等于声音与文字已精确配对**，也不证明归属和重叠问题已消失。
- **未消除的风险**：工作流仍有个案编号冲突与归属风险；训练读取器与数据 / 声音许可尚未核实；十分钟只是阶段检查量，**不是训练数据充分性的结论**。
- **不公开的范围**：本批次具体录音、真实转写文本、人工统计附件或链接、服务器 / 内网地址及私有目录一律不在本仓库发布；本节只说明方法状态，不提供可核验的数据样例。

### 私有审查包（只说用法，不提供任何附件或链接）

- 从私有渠道取得审查包后**下载并解压到本地**，用**系统浏览器**打开包内 HTML；HTML 与音频必须放在一起并保持相对目录，单独拷走 HTML 不会加载声音。
- 仓库源码预览只能看文本，**不运行页面**；评价请在浏览器内完成。
- 评价结果留在浏览器，按约定**导出后回传**给汇总人；不在公开仓库提交或粘贴任何评价内容、真实文本或统计表。
- **“只填异常”必须由评审者本人声明**。未声明时，缺失项保留显式的 `否` / `unknown` / `reject` / `改字`，并把**原始记录与解释后记录分别另存**；不能替其他评审者自动默认或补值。
- 不凭空断言任何下载渠道或客户端（包括微信）的限制；打不开或下载失败按实际环境排查，不以传闻代替验证。

## 先修实现问题，再比较模型

### 1. 最高优先级：试验片段与原录音时间错位

- 历史十分钟试验使用的是原录音第 10–20 分钟，但导出程序直接把片段内时间当作整段原录音时间，没有加回 600 秒。
- 公开整理前用现存文件核对：一个旧导出样段（长 1.27 秒，原始文件名不公开）对应原录音 **0.49 秒**处，而用于识别的小样在同一局部位置对应原录音 **600.49 秒**处。波形相似度分别约 0.999999 与 -0.002298；小样与原录音 600.49 秒处约 0.999753。这是程序核对，不是人工听感评分；本公开版不包含这些录音。
- [导出脚本](scripts/07_export.py)没有试验片段的原录音偏移量参数。**同类旧样段先隔离复查，不用于训练，也不直接用于比较转写模型。** 完整录音从零开始处理与这个错误场景不同。
- 接手修复要点：记录原文件、试验片段起点、局部起止时间及原录音起止时间；裁音频与配文字必须采用同一时间基准。验收至少覆盖“原录音从零开始”和“从中间截取”两种情况。

### 2. 整句话文字被贴到半句话音频上

- [当前导出脚本](scripts/07_export.py)只要检测段与一条转写结果重合超过 0.2 秒，就拼上那条转写的**全部文字**。
- 例如现存候选音频范围是 29.75–31.95 秒，匹配的两条转写范围却是 28.60–31.18、31.18–33.18 秒。匹配过程会带入切片以外的文字。
- [当前本机识别脚本](scripts/05_asr_whisper.py)关闭了逐字/逐词时间输出；[服务器适配脚本](scripts/06_asr_firered.py)也只保留句段，没有保留上游提供的逐字时间信息。
- 修复要点：优先在较长候选段上转写，再把文字逐字定位到声音中，最后按停顿、标点和字的边界裁片。不能继续用“稍有重合就贴整句”的规则。把文字定位到声音中称为**强制对齐（forced alignment，= 给已有文字找到声音位置）**；它只能帮助定位，不能把错误文字变正确。[1][2][3][5]

### 3. 识别到唱歌，不代表已经排除了唱歌

[导出脚本](scripts/07_export.py)只是跳过单独的音乐、唱歌标签行，**没有检查说话区间是否与唱歌区间重叠**。多种声音可以同时存在；不能声称当前已实现“唱歌重叠超过一半就丢弃”。相应的重叠判断、目标主播核验和多人同时说话检查仍需接手实现、验证。

### 4. 一些丢弃规则会损失正常内容

[当前配置](config/default.yaml)与[导出代码](scripts/07_export.py)会直接丢弃不足 1 秒、超过 15 秒、少于 4 字、估算语速过高或出现重复的候选。

- 超过 15 秒的正常说话目前是**整段丢弃**，不是按句子再切。
- 短句可以与相邻、同一说话人的句子合并；不能跨换人或同时说话区间强行合并。
- “对对对”等重复可能是主播真实说法。应以声音为准，不能把所有重复都认定为模型错误。
- 错贴整句文字会把短片段的估算语速抬高，继而误删。应先修文字对应关系，再调整过滤条件。
- 现有记录只有汇总丢弃数量，没有保存每条被丢候选的起止位置、文字和原因，暂时无法可靠复查损失发生在哪一步。

### 5. 改设置后可能仍在读取旧结果

[流程入口](scripts/run_file.sh)只检查中间文件是否存在，不核对模型、参数和参考声音是否变更。修改切分设置、参考音频或识别模型后，不能以为执行同一命令就重算了。对比实验使用**不同输出目录**；后续应记录每步的输入和设置，按依赖关系重新计算。

## 检索后的改进策略（建议，尚未完成接入和质量验证）

### U1：先找说话区域，再切完整表达

推荐顺序：

```text
原录音 + 明确的时间基准
  → 粗找说话区域，保留短暂停顿和两端余量
  → 在较长候选段上转写，保留上下文
  → 把文字逐字定位到声音中
  → 结合实际停顿、标点、换人位置，切成完整短句
  → 给每片只配属于它的文字，再检查质量
```

要点：

1. **说话检测不负责判断一句话是否说完。** 背景音乐不一定会造成切断；正常换气和短停顿也可能导致过碎切分。
2. FireRedVAD 已提供短静音合并、两端延伸等设置。[1] 可先小范围比较“合并间隔 0.3/0.5/0.7 秒、两端余量 0.1/0.2/0.3 秒”。这是本项目的待测参数，不是上游保证有效的推荐值。延长边界要防止夹入别人的声音。
3. 长候选先转写，再按实际字边界分段；超过下游训练时长限制时二次切分，不整段丢弃。保持音频与文字同时切分，禁止在字中间硬切。
4. 标点也可能错，不能只凭句号裁剪。强制对齐不准、边界仍不确定的片段进入人工复核，不强行放行。

### U2：分清歌词、识别错误和文字错配，再换模型

- **先修时间错位及整句错贴。** 否则更强模型的正确文字也可能被配给错误声音。
- 保留原始混音；对背景音乐明显的候选，增加一份分离后的人声用于转写对照。比较“同一模型读原音”和“同一模型读分离音”，不要一次换多个环节而无法判断改善来自哪里。[6]
- **歌词可能被正确识别，但不是主播的话。** FireRedASR2 和 Qwen3-ASR 的官方说明都包含歌声识别能力。[3][4] 换更强模型不等于自动排除背景歌声。需要用唱歌重叠提示、目标主播参考声音、多人同时说话检查及人工复核共同决定。
- 音乐标签只表示“检测到了音乐”，不是音乐响度，也不是污染程度；有音乐不必一刀切全部扔掉。
- 不同识别器意见不一致的片段优先复核；两个模型都写出同一段歌词也不能证明它属于主播。不得用文字润色程序凭空补出音频里没有的话。

### U3：提高“合格素材时长”，不是单纯放宽筛选

1. 先回收可修复内容：短段合并、长段按句二次切分、文字重新对应；不要先全局降低质量要求。
2. 每条候选记录源录音起止时间、每道规则的分数和丢弃原因。统计候选时长、导出时长、人工合格时长，避免只数文件。
3. 分成“合格 / 待复核 / 丢弃”三类。唱歌、低识别分数、分离失真等可疑项先进入待复核，保留回查依据。
4. 从每类丢弃原因中随机抽查，检查是否误删正常主播说话。**当前审核脚本没有生成被丢片段清单，需要补齐。**
5. 用一批素材调设置，另一批未参与调设置的素材验收。以“相同人工质量标准下，合格分钟数增加”为目标；不能靠重复或相互重叠的切片凑数量。

| FireRedASR2-AED + 标点处理 | U2 的中文转写候选；官方提供字/词时间、句段及分数 [3] | 要安装并验证上游环境，保留逐字结果；仍会转写歌声 | 有适配脚本，但未完成服务器端验收，不能称为已验证主选 |

> 表中 Qwen 一行的「未接入、未在本项目测试」只针对**较早公开快照**；当前私有批次已使用 Qwen3-ASR-1.7B + Qwen3-ForcedAligner-0.6B，详见上方「最新方法与当前状态」。公开脚本仍未包含对应实现。

**推荐接手顺序：修时间与文字映射 → 在同一小样上比较现有模型与 FireRedASR2-AED → 再单独测试分离辅助；Qwen 作为备选对照。** 不先跑全量，也不靠不断调高说话检测要求来解决所有问题。

有关分离需要纠正两点：

- “分离音频绝对不能训练”不是普遍定律。本项目目前从原录音导出是保守选择，但**这也会保留原背景音乐**。只有经试听确认背景足够干净的原音才能入库；若尝试用分离音训练，必须单独验证字音是否完整、音色是否改变及剩余音乐，不可直接替换所有音频。
- 当前分离分数是“人声分轨的幅度 / 其他分轨幅度之和”的粗略估计，不是有干净参考的真实噪声测量，也不能判断是否只有主播。旧文档用几条样段给出的“干净/脏”分界未经人工标定，**不能拿 20 或 30 分贝当通用合格线**。[分数实现](scripts/03_sep_score.py)

## 效果怎么验收

**你人工听 + 人工校对文字是核心验收，不由模型代填。** 建议先固定一批原录音窗口，覆盖安静说话、纯音乐、带歌词音乐、说话叠加音乐、多人同时说话、快速口语。先连续检查一个十分钟窗口及所有切片，再补充随机样段和被丢候选；边界听感与文字核对用原速，倍速只作初筛。
> 这里的十分钟窗口仅是**阶段检查量**，不是训练数据充分性的证明；当前私有批次的统计与附件不公开。

| 项目 | 记录方法 |
|---|---|
| 句子完整性 | 记被截字、丢首尾、截在半句话的位置；对照切片前后原音，不只听片段本身 |
| 目标主播纯度 | 记非主播、歌词、多人同时说话、明显背景音乐或失真；说不准的留待复核 |
| 文字准确性 | 人工逐字修正；区分识别错误与音频/文字错位 |
| 有效产量 | 合格片段去除重叠后累计分钟数，并记录每类错误及丢弃原因；不得用模型标记的“说话占比”代替 |
| 漏掉的好内容 | 检查连续原音和各类丢弃候选，统计其中本可保留的时长 |

统计文字错误时，**字符错误率（CER，= 错字漏字多字占比）** =（替换字数 + 漏字数 + 多字数）/ 人工参考文字字数。统一标点、数字、简繁处理规则；“有错句子的比例”是另一项指标，不能混叫错字率。

同一批音频、同一人工参考、同一质量标准下比较各路线，记录完整句比例、字符错误率、误留/误删数量和时长、人工合格分钟数及处理耗时。来源各异的公开榜单不能直接横比，更不能替代本任务验收。放行门槛需小组结合训练模型和交付时长确定，现阶段不宣称达标。

## 交接顺序与现有证据的边界

1. **先修时间与文字映射**：保留源文件起点；加入非零起点、跨切片文字、同一字不能重复归入相邻片段的检查。
2. **再解决句子切断**：合并短停顿、补首尾余量、逐字定位、长句二次切分；不能把更严的检测门槛当作句子恢复。
3. **再比较转写与分离**：相同音频上逐项替换，人工确认歌词、错字、失真是否减少。
4. **最后校准过滤与产量**：保存每条候选的判定、分数和丢弃原因；加入被丢内容复核，再评估全量运行。

现有[五个小测试](tests/test_gates.py)只覆盖区间合并和满幅样本统计，**不覆盖上述时间错位、文字配对、歌词过滤、句子完整性或训练质量**。本次未重跑模型，也未做 5090 全量验证。已过时的内部方案不随本公开版本发布；以本页的问题状态和证据边界为准。人工操作细节见[验收流程](docs/验收流程.md)。

## 检索来源（2026-11-19 核对官方说明）

1. [FireRedVAD：检测标签、静音合并及边界延伸设置](https://github.com/FireRedTeam/FireRedVAD)。支持相关参数，不保证句子语义完整。
2. [WhisperX：说话检测、转写、逐字对齐与限制](https://github.com/m-bain/whisperX)。对齐帮助定位，不能保证识别文本正确。
3. [FireRedASR2S：中文及歌声转写、字/词时间、句段及分数](https://github.com/FireRedTeam/FireRedASR2S)。官方普通话测试数字不是本项目直播录音的质量结论。
4. [Qwen3-ASR 与中文强制对齐器](https://github.com/QwenLM/Qwen3-ASR)。支持歌声和带背景音乐输入，不代表只转写目标主播。
5. [faster-whisper：逐词时间和内置说话检测](https://github.com/SYSTRAN/faster-whisper#word-level-timestamps)。当前仓库没有开启逐词时间。
6. [Demucs：音乐分轨范围、数据来源及用法](https://github.com/adefossez/demucs)。输出人声/乐器轨，不是指定说话人的分离保证。
