# 验收流程（以人工听与逐字核对为准）

当前结果尚不合格，问题状态及改进依据见 [README](../README.md)。先修时间错位与文字配错，再比较模型；否则会把配对错误算到模型头上。

## 1. 固定原录音和检查范围

- 连续检查一个十分钟窗口及其所有切片，另补安静说话、纯音乐、带歌词音乐、说话与音乐叠加、多人同时说话和快速口语的样段。
- 标清窗口在原录音中的起点。每条同时保留原录音位置、切片、自动文字、人工修正文字。
- 边界和文字核对用原速，必要时回听切片前后几秒。倍速只能初筛，不能据此宣布没有丢字。
- 用于调设置的素材与最后验收素材分开；对比不同方案时固定输入和人工参考。

## 2. 每条记录什么

| 项目 | 人工填写内容 |
|---|---|
| 声音与文字对应吗 | 是否来自同一原录音位置；不得拿错位样段判断识别器好坏 |
| 句子完整吗 | 是否截字、缺首尾或在不合适的半句话处断开 |
| 是目标主播吗 | 目标主播 / 非主播 / 无法判断 |
| 是否有干扰 | 歌词、其他人同时说话、明显音乐、声音失真分别记录 |
| 文字对吗 | 逐字修正，不润色、不凭上下文补原音里没有的话 |
| 最终判定 | 合格 / 待复核 / 丢弃，以及原因 |

## 3. 当前工具的能力边界

- [审核脚本](../scripts/09_review.py)只从已保留结果生成 `review.csv`（试听清单），不是人工判定。
- 它**没有生成** `discard_review.csv`（被丢片段的试听清单）。[导出脚本](../scripts/07_export.py)目前也没有保存被丢候选的逐条位置与原因；补齐后才能按丢弃原因抽查。
- 审核脚本按分离分数排序，但当前导出记录没有写入该分数，不能声称已经得到“干净、中间、最脏”三档。补齐分数前，只把它当待听列表。
- 现有“是否多人 / 是否主播 / 文字是否正确”三列不够：还需人工补充完整句、歌词、音乐、失真和逐字修正。

## 4. 分开统计，不混用指标

- 不合格片段比例：被人工判为不合格的输出条数 / 检查条数，并分列截断、非主播、歌词、音乐、文字错误。
- 有错句比例：至少有一个转写错误的句数 / 检查句数，**不等于字符错误率**。
- 字符错误率：替换、漏字、多字总数 / 人工参考字数；统一标点、数字及简繁处理口径。
- 合格时长：人工合格片段去除重叠后累计分钟数，不把待复核片段算进去。
- 损失情况：各类被丢候选中本可保留的数量和时长；按原因分层抽查时，不能把不同层的等量样本直接当整体比例。

## 5. 放行与重新计算

先在相同质量标准下比较“完整句是否增加、歌词和错字是否减少、合格分钟数是否增加、人工耗时是否可接受”，再由小组约定上线门槛。旧文档的 5%/20%/10% 并非已经验证的标准。

筛选线要分别依据人工标注的好坏样段校准；分数不一定呈现两个峰。只改导出规则时可以复用上游结果，但使用新成品目录。改切分、识别模型或参考声音时，应重新计算受影响的步骤；当前入口不会自动识别这种变化。
